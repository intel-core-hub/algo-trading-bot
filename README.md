# algo-trading-bot

暗号資産市場向けの自動売買戦略の構築・検証プロジェクト。

## スコープと役割分担

- **ここで作るもの**: 相場データ取得、特徴量/シグナル生成、バックテスト、リスク管理ロジック。
- **ユーザー側で行うこと**: 実際の取引所APIキー発行・保管、実資金での発注実行。
  自動発注コードはテストネット/ペーパートレード止まりとし、実弾運用は検証が十分に固まってから
  ユーザー自身の判断・操作で行う。

## 進め方

1. `src/data.py` — ccxtで公開データ(OHLCV)を取得しキャッシュ(ページングして長期履歴も取得可能。
   `python src/data.py <symbol> <timeframe> <total_bars>` でCLI実行可能)
2. `strategies/` — ルールベースの戦略ロジック(MAクロス/モメンタム/平均回帰/トレンドフォロー)
3. `src/backtest.py` — 自前の軽量バックテストエンジン。手数料・スリッページを考慮
4. `backtests/run_baseline.py` — 単純なtrain/test(in-sample/out-of-sample)分割で検証
5. `src/walk_forward.py` / `backtests/run_walk_forward.py` — ローリングwalk-forwardで
   パラメータ再最適化しながらout-of-sample検証(複数銘柄対応)
6. `src/features.py` / `backtests/run_ml_signal.py` — 特徴量エンジニアリング +
   RandomForest分類器ベースのシグナルをwalk-forwardで検証
7. 十分な検証を経てから、テストネットでの自動発注に進む

### 現状の結果 (2026-09-08時点)

**単純なtrain/test分割 (BTC/USDT 1h, 直近5000本)**: MAクロス・モメンタム・平均回帰
(ボリンジャーバンド式Zスコア、`strategies/mean_reversion.py`)の3戦略とも、手数料込みで
train/test両方buy-and-holdに負けた。特にモメンタムは取引回数が多くコスト負けが大きい。
検証期間全体が強い上昇トレンド(testはbuy&hold +22.77%、sharpe+3.65)だったため、平均回帰も
勝率50%前後ながら反発狙いのショートがトレンドと逆行して大きく負けた(test: return -32.63%,
sharpe -8.63)。

**walk-forward最適化 (BTC/USDT・ETH/USDT 1h, 直近20000本 ≈2.3年、train2000本/test500本を
ローリング、36 fold)**: train窓でグリッドサーチしたベストパラメータをtest窓にそのまま適用し、
全foldのtest窓を連結してout-of-sample評価。結果はさらに悪く、3戦略×2銘柄すべてで
out-of-sample連結リターンが-73%〜-96%、fold単位の勝率も14%〜42%しかなかった
(buy&holdはBTC +29.86%、ETH -7.56%)。foldごとの最良パラメータもバラバラで安定していない
(例: mean_reversionのwindow/entry_z/exit_zが上位3組でfold全体の半分にも満たない)。
これは「train窓での最良Sharpeを選ぶ」というナイーブな最適化がノイズにフィットしている
(過学習)ことを強く示唆しており、単純なテクニカル指標のグリッドサーチ最適化は、固定
パラメータより悪化させる場合すらある、という重要な教訓。

**頑健なパラメータ選択 (naive vs robust比較)**: `walk_forward.py` に
`robust_selector`を追加(train窓を4つのサブ期間に分割し、(平均Sharpe - 標準偏差)が
最大のパラメータを採用。取引回数が少なすぎるサブ期間があるパラメータは失格)。
naiveと比べてrobustはfold勝率が改善する傾向は出た(例: BTC ma_cross 31%→39%、
mean_reversion 28%→22%とまちまちだが全体的にドローダウンはやや浅くなった)ものの、
それでもout-of-sample連結リターンは-65%〜-95%と依然として壊滅的。つまり過学習を
抑えても赤字が黒字に転換するわけではなく、この3種の単純なテクニカル指標ベースの
シグナル(MAクロス・モメンタム・平均回帰)自体に、この検証対象(BTC/ETH 1h,
2024/05-2026/09)では手数料控除後のエッジがそもそも無い、というのが見えてきた。

**長期トレンドフォロー (`strategies/trend_following.py`, 日足換算50/200日MAクロスで
取引を極端に減らす)**: BTC/USDT 20000本のtrain/test分割で検証したところ、取引回数は
train4回・test2回まで激減し手数料の影響はほぼ消えたが、それでもtrain -50.81%、
test -21.04%とbuy&hold(train+27.73%、test-10.97%)に勝てなかった。**取引コストの
問題を取り除いても、方向性の予測自体が当たっていない**ことが確認できた。

**ML分類器ベースのシグナル (`src/features.py` + `backtests/run_ml_signal.py`)**:
リターン・ボラティリティ・MA乖離率・RSI・出来高Zスコアなど11特徴量から、12本先までの
リターンが±0.5%を超えるか(上昇/下落/横ばいの3クラス)をRandomForestで予測。
最初の実装では毎バー独立に再予測させてしまい、1foldあたり平均93〜95回も取引が発生して
コストで残高がほぼゼロになる(fold勝率0%/6%)というバグに近い結果になった。予測ホライズン
(12本)とポジション保有期間を一致させ、12本ごとにしか判断しないように修正したところ
(平均取引回数19〜20回/foldまで低下)、fold勝率は29%/20%まで改善したが、それでも
out-of-sample連結リターンはBTC -65.95%、ETH -96.47%(buy&hold: BTC+29.86%,
ETH-7.56%)。学習済みモデルの特徴量重要度は`vol_24`・`vol_72`(ボラティリティ)が
上位を占め、方向そのものよりボラティリティレジームに反応しているだけで、方向的中率も
train~50%・test~36%(3クラスなのでランダムは33%相当)とほぼ運と変わらなかった。

**現時点までの結論**: ルールベース4種(MAクロス/モメンタム/平均回帰/トレンドフォロー)、
walk-forwardでのnaive/robust再最適化、RandomForest分類器のいずれも、この検証対象
(BTC/ETH 1h, 2024/05-2026/09)では手数料控除後に一貫したエッジを示せなかった。
アプローチを変えるより先に疑うべきは「単純な価格ベースの特徴量だけでは、この市場・
この時間足に方向的な優位性が乗っていない」可能性。次のステップ候補:
(a) オンチェーン/資金調達率(funding rate)/オーダーブック不均衡など価格以外の特徴量、
(b) より長い時間足(4h/日足)でノイズを減らす、
(c) 「勝つ戦略を探す」から「複数の弱い戦略を組み合わせてリスク管理する」方向への転換。

## セットアップ

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
```

APIキーが必要になった場合は `.env` に置く(gitignore済み)。マーケットデータ取得自体は
公開エンドポイントのみを使うため、当面はAPIキー不要で進められる。
